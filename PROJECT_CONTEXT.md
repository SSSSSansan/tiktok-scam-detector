## 2. Идея решения

**Гибрид: мультимодальные «улики» + правила + LLM-судья + калибровка.**

Мошенничество в TikTok прячется в трёх местах: в **речи**, в **тексте/картинке на экране** и в **описании/хэштегах/профиле**. Проверка одной модальности легко обходится, поэтому берём все три (опора: статья «Beyond Metadata: Multimodal, Policy-Aware Detection of YouTube Scam Videos», ICWSM 2026 — мультимодальный подход дал лучший F1 и был устойчивее к обходу, чем одномодальные).

```
TikTok URL (или mp4)
   │
   ▼
[ingest]  видео + метаданные (описание, хэштеги, автор, био) + аудио .wav
   │
   ├─► [asr]     голос → текст с таймкодами           (OpenAI Whisper API)
   ├─► [frames]  кадры 1 шт/сек
   │      ├─► [ocr]  текст на кадрах + таймкоды        (EasyOCR / PaddleOCR)
   │      └─► [vlm]  описание 3–5 ключевых кадров      (OpenAI vision-модель)
   └─► [meta]    описание, хэштеги, био
   │
   ▼
Evidence Pack (единый JSON, см. раздел 5)
   │
   ├─► [features]  регулярки/признаки (TG/WA-ссылки, «гарантия», «x2», urgency и т.д.)
   └─► [llm_judge] LLM по rubric'у → категория + скор + объяснение (OpenAI GPT)
   │
   ▼
[calibrate]  логистическая регрессия поверх (признаки + скор LLM) → финальный risk 0..1
   │
   ▼
Результат: {risk, category, evidence[с таймкодами]}
```

Дополнительно обязательно:
- **Бейзлайн для сравнения:** TF-IDF по описанию+хэштегам → логистическая регрессия.
- **Ablation:** только текст / только аудио / только визуал / всё вместе.
- **Adversarial/edge-case тесты:** видео без речи, видео без текста на экране, обфускация («инв3стиции»), казахский язык, безобидное видео со словом «деньги».
- **Объяснимость:** каждый вердикт сопровождается уликами с таймкодами.

## 3. Категории (ровно 6 меток, менять нельзя)

Каждому видео — **одна** метка:

| Метка | Значение |
|---|---|
| `investment_platform` | Фейковая инвестиционная платформа: «вложи — получи доход», трейдинг-боты, «гарантированная прибыль» |
| `pyramid` | Финансовая пирамида: «приведи друга — получи %», упор на вербовку |
| `betting` | Реклама нелегального беттинга: «100% прогноз», «кэф гарантирован» |
| `giveaway` | Фейковая раздача/розыгрыш: «подпишись и выиграй iPhone», сбор данных под видом конкурса |
| `job_offer` | Фейковая вакансия: «работа из дома, X тг/неделю», «купи стартовый пакет» |
| `none` | Не скам |

Правила разметки:
- Метка `none` — не меньше ~50% датасета. Обязательны **hard negatives**: настоящие финансовые блогеры, реальные вакансии, официальные розыгрыши брендов с verified-аккаунтов, бытовые видео. Иначе модель выучит «слово "деньги" = скам».
- Разметка двойная: два человека независимо, расхождения разбираем втроём; считаем **Cohen's kappa**.
- `risk score` — не метка вручную, а выход системы (0..1). Для `none` ожидается низкий риск.

## 4. Датасет

Готового датасета нет — **собираем сами** (ориентир: 150–220 видео). Единая таблица `data/labels.csv`.

### Схема `data/labels.csv`

| Колонка | Описание |
|---|---|
| `video_id` | ID TikTok-видео (числовой, из URL) |
| `url` | Ссылка на видео |
| `found_by` | Кто нашёл: `panda` / `arai` / `aigerim` |
| `label_1` | Метка первого разметчика (одна из 6) |
| `label_2` | Метка второго разметчика |
| `label_final` | Итоговая метка после разбора расхождений |
| `language` | `ru` / `kk` / `mixed` |
| `has_speech` | `1` / `0` — есть ли речь |
| `has_onscreen_text` | `1` / `0` — есть ли текст на экране |
| `format` | `talking_head` / `voiceover_text` / `text_only` / `speech_only` / `screenshots_montage` |
| `is_hard_negative` | `1` для «похожих на скам, но честных» |
| `split` | `train` / `test` (стратифицированно, ~60/40) |
| `notes` | Комментарии |

### Требования к составу
- Языки: русский + казахский (казахского хотя бы 20–30%), допускается смесь.
- Форматы: разнообразные. Отдельно **10–15 видео без речи** (музыка + текст) и **10–15 видео без текста на экране** — это edge-case тесты.
- Скам-классы: примерно поровну по 5 категориям.
- Только публичные видео, открывающиеся без VPN/логина.

### Где искать
- Хэштеги/запросы (ru): `#заработок`, `#инвестиции`, `#пассивныйдоход`, `#трейдинг`, `#прогнозы`, `#ставки`, `#розыгрыш`, `#конкурс`, `#удаленнаяработа`, `#работаизсм`.
- (kk): `#табыс`, `#инвестиция`, `#жұмыс`.
- Разоблачительные подборки: `#развод`, `#мошенники`, `#scamalert` — там уже отобран подозрительный контент.
- Для `none`: настоящие финансовые блогеры, вакансии известных компаний, розыгрыши верифицированных брендов, случайные бытовые ролики.
- Внешний датасет **VidScam** (YouTube, англ.) — только как дополнительная проверка на чужих данных, не как основной.

### Скачивание
`yt-dlp` (`yt-dlp "https://www.tiktok.com/@user/video/ID"`). Если TikTok блокирует — запасной путь: скачать mp4 вручную и положить в `data/videos/<video_id>.mp4`. Пайплайн должен принимать и URL, и локальный mp4.

## 5. Контракты данных (JSON между модулями)

Каждый модуль — функция Python, принимающая/возвращающая dict ровно в этом формате.

**ingest → `IngestResult`**
```json
{
  "video_id": "7417328428443110663",
  "video_path": "data/videos/7417328428443110663.mp4",
  "audio_path": "data/cache/7417328428443110663.wav",
  "meta": {
    "description": "...",
    "hashtags": ["заработок", "инвестиции"],
    "author": "username",
    "author_bio": "..."
  }
}
```

**asr → `AsrResult`**
```json
{
  "language": "ru",
  "text": "полный транскрипт",
  "segments": [{"start": 4.2, "end": 7.9, "text": "гарантирую доход сорок процентов"}]
}
```

**frames → список кадров:** `[{"t": 4.0, "path": "data/cache/<id>/frame_0004.jpg"}, ...]`

**ocr → `OcrResult`**
```json
{
  "items": [{"t": 4.0, "text": "t.me/fastmoney  +300%", "confidence": 0.91}]
}
```

**vlm → `VlmResult`**
```json
{
  "items": [{"t": 4.0, "description": "скриншот торгового приложения с зелёными цифрами роста"}]
}
```

**features → `FeaturesResult`**
```json
{
  "flags": {"has_telegram_link": 1, "guaranteed_income_phrase": 1, "urgency_words": 0, "referral_phrase": 0},
  "matches": [{"flag": "has_telegram_link", "source": "ocr", "t": 4.0, "text": "t.me/fastmoney"}]
}
```

**Evidence Pack** (собирается в `pipeline.py` из всего выше): `{ingest, asr, ocr, vlm, features}`.

**Итоговый ответ системы (`Verdict`)**
```json
{
  "video_id": "7417328428443110663",
  "risk": 0.87,
  "category": "investment_platform",
  "evidence": [
    {"t": 4.0, "source": "ocr", "text": "t.me/fastmoney +300%"},
    {"t": 11.2, "source": "asr", "text": "гарантирую доход сорок процентов"}
  ],
  "explanation": "Короткое объяснение на человеческом языке."
}
```
Допустимые значения `category`: строго 6 меток из раздела 3.

## 6. Технический стек

| Блок | Инструмент |
|---|---|
| Язык | Python 3.10+ |
| Скачивание | `yt-dlp`, `ffmpeg` |
| Кадры | `opencv-python` |
| ASR | OpenAI Whisper API (запасной вариант — `faster-whisper`, для казахского есть дотюненная `shyngys879/kazakh-whisper-large-v3-turbo`) |
| OCR | EasyOCR или PaddleOCR (языки: ru, en, kk/кириллица) |
| VLM | OpenAI vision-модель по API (запасной вариант — Qwen3-VL-8B через OpenRouter) |
| LLM-судья | OpenAI GPT по API, строгий JSON-ответ, few-shot из нашей разметки |
| Признаки/бейзлайн/калибровка | `scikit-learn`, `pandas` |
| Демо | Streamlit (или FastAPI + Streamlit) |

Секреты: ключ OpenAI хранится **только** в `.env` (в `.gitignore`!), в репозиторий не коммитим. Пример — `.env.example` с пустым `OPENAI_API_KEY=`.

## 10. Известные риски

- TikTok может блокировать `yt-dlp` (особенно с серверных IP) → качать локально, держать fallback на ручной mp4.
- Мало данных и перекос классов → следить за балансом, считать macro-метрики.
- Нет hard negatives → ложные срабатывания на любой финансовой теме.
- Task 2 неизвестен → уточнить у научного руководителя в понедельник.
- Стоимость/лимиты OpenAI API → кэшировать все ответы (`data/cache`), не гонять одно видео дважды.
- Интернет/TikTok могут подвести на защите → заранее записанное видео-демо.

## 12. Инструкция для LLM-ассистента

1. Прочитай разделы 1–3 и 5 — это неизменяемая основа.
2. Спроси (или определи по контексту), с кем из команды ты работаешь, и открой её/его блок в разделе 8.
3. Посмотри STATUS и возьми первую незакрытую задачу этого человека; не дублируй чужие модули.
4. Код пиши в формате, совпадающем с контрактами из раздела 5; давай полные файлы, а не фрагменты.
5. Не коммить секреты; все вызовы платных API кэшируй.
6. В конце работы предложи точные строки для обновления раздела STATUS и журнала изменений.
7. Не придумывай метрики и результаты — только то, что реально посчитано на нашем датасете.
